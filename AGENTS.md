# AGENTS.md

Guidance for coding agents working in this repository.

## Project Overview

Spring Boot REST API for pegawai (employee) CRUD.

- Java 25, Gradle 9.8.1 (Kotlin DSL)
- Spring Boot 4.1.1
- PostgreSQL 18 via Docker Compose
- Spring Data JPA / Hibernate 7 with Flyway migrations
- MapStruct + Lombok for mapping and boilerplate
- springdoc OpenAPI UI
- Virtual threads enabled

## Common Commands

```bash
# Start local infrastructure (Postgres on 5432, Adminer on 8083)
docker compose up -d

# Run the application (Flyway migrations run automatically on startup)
./gradlew bootRun

# Compile only
./gradlew compileJava

# Run tests (requires Postgres to be running)
./gradlew test

# Stop infrastructure
docker compose down

# Stop and delete database volume (destructive)
docker compose down -v
```

Database credentials/defaults (see `compose.yml` and `application.yaml`):

- URL: `jdbc:postgresql://localhost:5432/crud`
- Username: `admin`
- Password: `admin`

Overridable with `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`.

## Package Structure (layer-first)

```
com.example.demo
├── config/       # JPA auditing and other configuration
├── controller/   # REST endpoints
├── dto/          # Java records for request/response
├── entity/       # JPA entities
├── exception/    # Custom exceptions + global handler
├── mapper/       # MapStruct mappers
├── repository/   # Spring Data JPA repositories
└── service/      # Business logic, transaction boundaries
```

Keep new features in these layers. Do not add a parallel package structure without a clear reason.

## Coding Conventions

### Entities

- Extend `BaseEntity`. It provides `id`, `uuid`, audit fields, and soft-delete fields.
- `id` is `BIGINT GENERATED ALWAYS AS IDENTITY` and is internal only. Never expose it.
- `uuid` is UUID v4 (generated by Hibernate `@UuidGenerator`) and is the public identifier.
- Use Lombok `@Getter` / `@Setter`; entities must not be Java records.
- `@SQLRestriction("deleted_at is null")` lives on `BaseEntity`, so all entities automatically hide soft-deleted rows.
- Soft delete only: set `deletedAt` (and `deletedBy` when available). Never hard delete.

### DTOs

- Always Java records.
- Request records carry Jakarta Validation annotations (`@NotBlank`, `@Size`, `@Past`, etc.).
- Response records expose only `uuid` and business fields.
- Never expose `id`, `fk_id`, or audit columns (`*_at`, `*_by`) to clients.
- Use `PageResponse<T>` for paged responses.

### Mapping

- Use MapStruct with `componentModel = SPRING` and `unmappedTargetPolicy = ERROR`.
- Ignore internal fields (`id`, `uuid`, audit, soft-delete) when mapping request to entity.
- Do not edit generated `*MapperImpl` classes; they live under `build/generated`.

### Services

- Concrete `@Service` classes (no interface unless explicitly required).
- Put transaction boundaries here: `@Transactional` for writes, `@Transactional(readOnly = true)` for reads.
- Throw `ResourceNotFoundException` for missing active records and `DuplicateResourceException` for conflicts.
- Use `AuditorAware<Long>` for `*_by` fields. It currently returns empty until authentication exists, so audit-by columns are nullable.

### Controllers

- Base path: `/api/v1/<resource>`.
- Use `@Valid` on request bodies.
- Return DTOs, never entities.
- `POST` returns `201`, `DELETE` returns `204`.

## Database and Migrations

- Schema changes are managed by Flyway only. `spring.jpa.hibernate.ddl-auto` is `validate`.
- Migrations live in `src/main/resources/db/migration`.
- Name new migrations `V<next>__<snake_case_description>.sql` (for example `V3__add_jabatan_table.sql`).
- Never modify a migration that has already been applied; add a new one instead.
- UUID uses a hash index only (no unique constraint). NIP is unique among active rows via a partial index.
- Indexes should support actual query patterns; avoid redundant indexes.

## Foreign Key Convention

When adding relations in the future:

- Database/entity column: `fk_id BIGINT` (references the target's `id`).
- DTO/API field: `fkUuid UUID` (references the target's `uuid`).
- Resolve `fkUuid` to the entity via the repository in the service or mapper.
- Never expose `fk_id` to clients.

## API Endpoints

```
POST   /api/v1/pegawai
GET    /api/v1/pegawai?search=&page=&size=&sort=
GET    /api/v1/pegawai/{uuid}
PUT    /api/v1/pegawai/{uuid}
DELETE /api/v1/pegawai/{uuid}
```

Errors are returned by `GlobalExceptionHandler` as `ErrorResponse`:

- `400` validation/type mismatch
- `404` not found
- `409` duplicate NIP
- `500` unexpected error (details are logged, not leaked)

## Testing

- `./gradlew test` boots the Spring context against the real Postgres instance.
- Postgres must be running before tests.
- Testcontainers is not set up yet. If tests need isolation, prefer adding Testcontainers over mocks for persistence.
- Clean up manual smoke-test data with `TRUNCATE` only in the local development database.

## Things to Avoid

- Editing applied Flyway migrations.
- Using `ddl-auto: update/create/create-drop`.
- Hard deletes or bypassing `deleted_at`.
- Native queries without an explicit `deleted_at is null` filter (`@SQLRestriction` does not apply to native SQL).
- Exposing entities, numeric IDs, `fk_id`, or audit fields in API responses.
- Replacing derived queries with ad-hoc SQL without a reason.

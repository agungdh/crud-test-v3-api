# AGENTS.md

Guidance for coding agents working in this repository.

## Project Overview

Spring Boot REST API for pegawai (employee) CRUD. Single Gradle module, package root `com.example.demo`.

- Java 25 toolchain, Gradle 9.8.1 wrapper
- Spring Boot 4.1.1 — Boot 4 starter names apply (`spring-boot-starter-webmvc`, `spring-boot-starter-webmvc-test`), not `-web`
- PostgreSQL 18 via Docker Compose; Flyway owns the schema; `spring.jpa.hibernate.ddl-auto: validate`
- Spring Data JPA / Hibernate 7, MapStruct 1.6.3, Lombok, springdoc OpenAPI
- Virtual threads enabled; JPA `open-in-view` is `false`

`HELP.md` is untouched Spring Initializr boilerplate; this file is the project documentation.

## Common Commands

```bash
# Start local infrastructure (Postgres on 5432, Adminer on 8083; both bound to 127.0.0.1)
docker compose up -d

# Run the application (Flyway migrations run automatically on startup)
./gradlew bootRun

# Compile only (fast sanity check)
./gradlew compileJava

# Run tests (boots Spring against the real Postgres)
./gradlew test

# Run one test class
./gradlew test --tests 'com.example.demo.DemoApplicationTests'

# Stop infrastructure
docker compose down

# Stop and delete database volume (destructive)
docker compose down -v
```

Database defaults (see `compose.yml` and `application.yaml`):

- URL: `jdbc:postgresql://localhost:5432/crud`
- Username: `admin`
- Password: `admin`

Override with `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`.

## Package Structure (layer-first)

```
com.example.demo
├── config/       # JPA auditing (AuditorAware placeholder)
├── controller/   # REST endpoints
├── dto/          # Java records for request/response
├── entity/       # JPA entities
├── exception/    # Custom exceptions + GlobalExceptionHandler
├── mapper/       # MapStruct mappers
├── repository/   # Spring Data JPA repositories
└── service/      # Business logic and transaction boundaries
```

Keep new features in these layers; do not introduce a parallel structure without a clear reason.

## Coding Conventions

### Entities

- Extend `BaseEntity`. It provides `id`, `uuid`, audit fields, and soft-delete fields.
- `id` is `BIGINT GENERATED ALWAYS AS IDENTITY` and is internal only. Never expose it.
- `uuid` is generated by Hibernate `@UuidGenerator(style = RANDOM)` and is the public identifier.
- `uuid` has only a non-unique hash index; service lookups use `findFirstByUuidOrderByIdAsc(uuid)`.
- Use Lombok `@Getter` / `@Setter`; entities are not records.
- `@SQLRestriction("deleted_at is null")` lives on `BaseEntity`, so all entity (JPQL) queries hide soft-deleted rows automatically.
- Soft delete only: set `deletedAt` and `deletedBy` (when available). Never hard delete.

### DTOs

- Always Java records.
- Request records carry Jakarta Validation annotations (`@NotBlank`, `@Size`, `@Past`, etc.).
- Response records expose only `uuid` and business fields.
- Never expose `id`, `fk_id`, or audit columns (`*_at`, `*_by`) to clients.
- Use `PageResponse<T>` for paged responses (`content`, `page`, `size`, `total_elements`, `total_pages`).
- JSON is snake_case globally (`spring.jackson.property-naming-strategy: SNAKE_CASE`); keep Java fields camelCase and do not add per-field `@JsonProperty` just for casing.

### Mapping

- MapStruct with `componentModel = SPRING` and `unmappedTargetPolicy = ERROR`.
- Ignore `id`, `uuid`, audit, and soft-delete targets in request→entity mappings.
- Generated `*MapperImpl` classes land in `build/generated/sources/annotationProcessor/java/main`; never edit them.

### Services

- Concrete `@Service` classes with constructor injection (`@RequiredArgsConstructor`); no interfaces unless explicitly required.
- Transaction boundaries belong here: `@Transactional` for writes, `@Transactional(readOnly = true)` for reads.
- Because `open-in-view` is `false`, lazy loading must happen inside the service transaction.
- Throw `ResourceNotFoundException` for missing active records and `DuplicateResourceException` for conflicts.
- `AuditorAware<Long>` currently returns `Optional.empty()` (no auth yet), so `*_by` columns stay null; `deletedBy` is only set when an auditor exists.

### Controllers

- Base path: `/<resource>` (no API version prefix).
- Use `@Valid` on request bodies.
- Return DTOs, never entities.
- `POST` returns `201`, `PUT` returns `200`, `DELETE` returns `204`.
- List endpoint uses `@PageableDefault(size = 10, sort = "nama")`; search matches `lower(nama)` against a lowercased pattern and `nip` with a plain `like`.
- springdoc defaults: Swagger UI at `/swagger-ui.html`, spec at `/v3/api-docs`.

## Database and Migrations

- Flyway owns schema changes; migrations live in `src/main/resources/db/migration` (currently `V1`; next is `V2`).
- Name migrations `V<next>__<snake_case_description>.sql`.
- Never modify an applied migration; add a new one.
- NIP is unique among active rows via the partial index `uq_pegawai_nip_active`; the service also pre-checks with `existsByNip`. A race that bypasses the pre-check would surface as a generic `500`.
- Prefer derived/JPQL queries that benefit from `@SQLRestriction`; indexes should match real query patterns.

## Foreign Key Convention

When adding relations:

- Database/entity column: `fk_id BIGINT` (references the target's `id`).
- DTO/API field: `fkUuid UUID` (references the target's `uuid`).
- Resolve `fkUuid` to the entity via the repository in the service.
- Never expose `fk_id` to clients.

## API Endpoints

```
POST   /pegawai
GET    /pegawai?search=&page=&size=&sort=
GET    /pegawai/{uuid}
PUT    /pegawai/{uuid}
DELETE /pegawai/{uuid}
```

Errors are returned by `GlobalExceptionHandler` as `ErrorResponse`:

- `400` validation errors / type mismatch
- `404` not found
- `409` duplicate NIP
- `500` unexpected error (details are logged, not leaked)

## Testing

- `./gradlew test` boots the full Spring context against the real Postgres instance; start Docker first.
- The only test today is `DemoApplicationTests.contextLoads`; there is no Testcontainers setup yet.
- If new tests need isolation, prefer adding Testcontainers over mocks for persistence.
- Clean up manual smoke-test data with `TRUNCATE` only against the local development database.

## Things to Avoid

- Editing applied Flyway migrations.
- Using `ddl-auto: update/create/create-drop`.
- Hard deletes or bypassing `deleted_at`.
- Native queries without an explicit `deleted_at is null` filter (`@SQLRestriction` does not apply to native SQL).
- Exposing entities, numeric IDs, `fk_id`, or audit fields in API responses.
- Replacing derived queries with ad-hoc SQL without a reason.
- Assuming authentication exists; there is currently no security layer.
